# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Blitztext is an experimental **macOS menubar app** (Swift/SwiftUI + AppKit) for speech-to-text with optional AI rewriting. A hotkey (or menu click) records the mic, transcribes it, optionally transforms the text with an LLM, and auto-pastes the result into the frontmost app.

This fork adds a **fully-offline path**: local WhisperKit transcription plus a local, OpenAI-compatible LLM server (llama.cpp `llama-server`) for the rewrite/translate/summarize/format features — no cloud needed.

## Build & run

Requires **Xcode 16+**, **XcodeGen** (`brew install xcodegen`). The `.xcodeproj` is generated by XcodeGen from `BlitztextMac/project.yml` on every build (do not hand-edit the project; edit `project.yml`). Source folders are globbed by directory, so **new `.swift` files under `BlitztextMac/{App,Features,Services,Views}` are picked up automatically** — no project edit needed.

```bash
./build.sh              # generate project, build universal (arm64+x86_64) Release, ad-hoc sign → ./Blitztext.app
./build.sh --install    # also copy to /Applications and sign there
./build.sh --run        # launch after building
./build.sh --debug      # Debug configuration
```

There is no test suite, linter, or CI build step in this repo.

### Code signing & the Accessibility/TCC trap

`build.sh` signs with the **`Blitztext Local Signing`** identity if it exists in the login keychain, otherwise falls back to ad-hoc (`-`). This matters: macOS ties the Accessibility (auto-paste) permission to the code signature. **Ad-hoc builds get a new cdhash every build → the Accessibility grant resets on every install.** A stable self-signed cert keeps the grant across rebuilds. If auto-paste stops working after an install, the grant was reset — re-enable Blitztext under System Settings → Privacy → Accessibility (or `tccutil reset Accessibility app.blitztext.mac` then re-grant). Bundle id: `app.blitztext.mac`.

## Local offline LLM server

The rewrite features talk to an OpenAI-compatible endpoint. For offline use, a local `llama-server` (from `brew install llama.cpp`) serves a GGUF model:

```bash
./start-local-llm.sh    # starts llama-server on http://localhost:8080/v1
```

- The app can also **auto-start/stop** this server itself — see `LocalLLMServerService` (spawned from `AppDelegate`, gated on `appSettings.localLLMEnabled` + `localLLMAutostart`; it skips spawning if a server is already reachable on the port).
- **Server flags matter**: use `--jinja` (applies the GGUF's embedded chat template). For **Qwen3** models pass `--reasoning on` (the app-managed launch and `start-local-llm.sh` do this automatically for `*qwen3*` filenames) — `--reasoning off` makes Qwen3 run away.

## Architecture (the big picture)

**Entry point & lifecycle** — `BlitztextMacApp.swift` holds `AppDelegate` (an `NSStatusItem` menubar app, `.accessory` activation policy). It owns the single `AppState`, the `MenuBarStatusController`, and the `LocalLLMServerService`, and wires global hotkeys and the popover.

**`AppState` (`App/AppState.swift`)** is the central `@Observable @MainActor` hub: holds all settings, the `activeWorkflow`, menubar status, and the paste logic. `startWorkflow(_:)` instantiates the right workflow per `WorkflowType`; `isWorkflowAvailable(_:)` gates each mode; `handleWorkflowOutput(_:)` is the single chokepoint where the final text is corrected (learned corrections), space-normalized, and pasted at the cursor via a synthesized Cmd+V (`CGEvent`).

**Workflows (`Features/Workflows/`)** — each mode is a class conforming to `Workflow` (start/stop/reset + `phase`). Two-phase pattern: **Phase 1** transcribe (via `TranscriptionService.transcribe(..., backend:)` which routes remote/local), **Phase 2** LLM transform (via `LLMService`). `TranscriptionWorkflow` is dictation-only; `TextImprovement/DampfAblassen/EmojiText/Translate/Summarize` follow the two-phase pattern; `FormatWorkflow` shows a format chooser (bullets/email/todo) *before* recording.

**`WorkflowType` enum (`Features/Workflows/WorkflowProtocol.swift`)** is the identity used everywhere. ⚠️ **Adding a new mode means updating every exhaustive `switch WorkflowType` in the codebase** — the enum's own computed props, plus switches in `AppState` (`startWorkflow`, `isWorkflowAvailable`, `workflowSubtitle`), `MenuBarView` (`workflowIconColor`, workflow-page switch + a new ActiveView), and **`MenuBarStatusController`** (icon animation + badge symbol switches). Grep for `case .emojiText` to find them all. Also wire the hotkey in `HotkeyService` if it needs one (all `fn`+single-modifier combos are taken; new modes are usually menu-launched).

**Services (`Services/`)**
- `LLMService` — the rewrite/translate/summarize/format backend. `LLMConfig` selects OpenAI vs a local base URL. Read `AppState.llmConfig`.
- `TranscriptionService` — OpenAI Whisper (remote) + a `backend` router that delegates to `LocalTranscriptionService` for local.
- `LocalTranscriptionService` — WhisperKit/CoreML on-device transcription; downloads/loads models from `~/Library/Application Support/Blitztext/models/whisperkit/`.
- `KeychainService` — stores the OpenAI API key. `HotkeyService` — global `flagsChanged` monitor mapping `fn`+modifier combos to workflows. `AudioRecorder`, `AccessibilityPermissionService`, `LaunchAtLoginService`, `BlitztextCleanupService`, `BlitztextInstallLocationService`.

**Settings persistence** — all settings structs are serialized as one `SettingsContainer` JSON at `AppSupportPaths.settingsURL`. **New optional fields must be decoded with `decodeIfPresent` + a default** (see `AppSettings.init(from:)`) or loading old files fails and everything resets.

**Menubar icon** — `MenuBarStatusController` renders the animated status icon (`MenuBarStatusIconRenderer` = classic stripes, `MenuBarRingIcon` = modern ring), chosen by `appSettings.useModernTheme`. `MenuBarView` is the popover UI (frosted-glass "modern" theme gated by the same flag).

## Working with the local LLM (important gotcha)

The local model in use (`Qwen3-8B` i1 quant) is an unreliable instruction-follower for transformation tasks — it echoes the prompt, loops, appends chatty tails, or answers conversationally. `LLMService` mitigates this heavily for the **local** path: instruction goes in the **user** message (not system), `repeat_penalty: 1.1` (1.15 mangles German words), an expanded `stop` list, and `sanitizeLocalOutput(...)` which post-trims runaway tails / prompt-echoes / preambles / meta-phrases (the correct answer is always at the start). Translate uses a directed **few-shot** prompt (its own reliable path). When changing prompts, verify against the running server with `curl http://localhost:8080/v1/chat/completions`, running several reps — failures are intermittent. A dedicated non-reasoning instruct model (e.g. Qwen2.5-7B-Instruct) would be far more reliable; the model is swappable via the `.gguf` path in settings.
